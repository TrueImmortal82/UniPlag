# UniPlag & ICG v0.4.1 — Стандарты разработки и интеграция в университетские системы

## 1. Технологический стек

| Компонент | Технология |
|---|---|
| Язык | Python 3.10+ |
| Веб-фреймворк | FastAPI ≥ 0.110 + Uvicorn |

## 2. Стандарты кода

### 2.1 Общие правила
- Код размещается в пакете `app/`, точки входа — в корне (`run_server.py`, `UniPlag_Start.bat`).
- Скрипты автоматизации — в `scripts/`.
- Один модуль = одна ответственность (проверка, детекция, ICG, криптография, парсинг — разделены).
- Типизация: используются `Mapped[int | None]`, `dataclass`, аннотации типов.
- Комментарии и докстринги — на русском/английском, по одному стилю в модуле.

### 2.2 Структура модулей
```
app/
  main.py          — маршруты, дашборды
  api.py           — JSON API (интеграционный контур)
  checker.py       — асинхронный пул проверок
  plagiarism.py    — шинглинг/W-shingling, поиск заимствований
  ai_detector.py   — AI-детекция текста
  icg/             — граф интеллектуального вклада (DAG)
  parsing.py       — мультиформатный парсер
  pdf_certificate.py — PDF-сертификаты с 512-bit печатью
  integrity.py     — анти-взлом, манифест, HMAC-подписи
  trusted_nodes.py — авторизация рабочих машин
  consensus.py     — блокчейн-реестр изменений
  auth.py / security.py — сессии и пароли (PBKDF2-HMAC-SHA256, 200k итераций)
  config.py        — конфигурация (env-переменные UNIPLAG_*)
```

### 2.3 Процесс изменений кода
1. Внесение правок в исходники (`app/`, шаблоны, скрипты).
2. **Согласование через контур 512-bit**: `scripts/approve_changes.py` или `/admin/consensus` подписывают изменения мастер-ключом.
3. Каждое согласование создаёт блок в криптографическом реестре (`.security/audit_ledger.jsonl`) с SHA-512 хэшем цепочки.
4. Проверка целостности при старте: манифест `.integrity_manifest.json` сверяется с файлами; любые несогласованные правки фиксируются.
5. Модифицировать защищённые файлы может только доверенная машина из реестра (`.security/trusted_developers.json`) с валидной HMAC-SHA512 подписью.

### 2.4 Безопасность и криптографический контур
- **512-bit мастер-ключ** хранится вне Git (`.security/sovereign_512.key`), задаётся env `UNIPLAG_SOVEREIGN_KEY_512`.
- **Манифест целостности** — SHA-256 хэши всех `.py/.html/.css/.json` + HMAC-SHA512 подпись.
- **Анти-монитогом патчинга** — проверка байткода критических функций в рантайме.
- **Печать проверок** — каждый отчёт получает HMAC-SHA512 печать `UP-NNNNN-HEX32`; публичная проверка на `/verify/{seal}` без авторизации.
- Пароли — PBKDF2-HMAC-SHA256, 200 000 итераций, соль 16 байт.
- Сессии — cookie `uniplag_session`, 256-bit токен (хеш в памяти; теряются при перезапуске).

## 3. Интеграция в университетские системы

### 3.1 Готово сейчас (без доработок)

| Возможность | Эндпоинт | Назначение |
|---|---|---|
| JSON API проверки текста | `POST /api/check-text` | Отправка работы + получение всех метрик JSON |
| Статус асинхронной проверки | `GET /api/checks/{id}/status` | Поллинг прогресса |
| Полные результаты | `GET /api/checks/{id}` | Оригинальность, плагиат, AI, ICG, фрагменты |
| ICG-граф как JSON | `POST /api/icg/graph` | Глубинный анализ для научных отделов |
| Здоровье сервиса | `GET /api/health` | Мониторинг (Zabbix/uptime) |
| Публичная проверка сертификата | `GET /verify/{seal}` | Верификация PDF-печатей третьими лицами |
| PDF-сертификат | `GET /report/{id}/pdf?lang=ru/en` | Официальный A4 аттестат с 512-bit печатью |
| Сбор корпуса по URL | `POST /api/crawl` | Программное пополнение базы источников |
| Аттестация целостности | `GET /api/integrity` | Отчёт для ИБ-отдела вуза |

### 3.2 Варианты интеграции с типовыми системами вуза

**LMS / Moodle / платформы электронного обучения**
- Модуль отправляет текст ВКР/курсовой через `POST /api/check-text`, получает JSON с метриками и отображает результат в интерфейсе личного кабинета.
- Аутентификация по cookie — для внутрисерверного контура достаточно SFTP/HTTPS-прокси.

**Портал вуза / 1С / деканат**
- Автоматическая выгрузка результатов проверок (JSON → портал, Excel, распределённая печать сертификатов).
- Импорт списков студентов из существующей СУБД через продление моделей `users`/`checks`.

**Антиплагиат и научные архивы**
- Встроенный контур научного поиска (OpenAlex, Crossref, arXiv) позволяет проверять против открытых источников; расширение возможно добавлением внешних баз через адаптеры.

**Единая система мониторинга**
- `GET /api/health` + журналы (`logs/error.log`) пригодны для подключения к SIEM.

### 3.3 Требует доработки (roadmap)
| Потребность | Статус | Необходимое изменение |
|---|---|---|
| OAuth2 / SSO (SAML, LDAP, Keycloak) | Нет | Добавить OAuth2/OpenID в `api.py` и `auth.py` |
| API-ключи / Bearer-токены для сторонних систем | Нет | Ввести подпись запросов HMAC или JWT |
| REST по пользователям и работам | Нет | CRUD-эндпоинты: `users`, `documents`, `checks` |
| Экспорт в Excel/CSV | Нет | Endpoint выгрузки рейтингов/проверок |
| Пул async-корпоративная база (PostgreSQL) | Опционально | Переключить `UNIPLAG_DATABASE_URL` на Postgres |
| MQ (RabbitMQ/Kafka) для массовых очередей проверок | Нет | Адаптер событий в `checker.py` |
| Webhook уведомлений о завершении проверок | Нет | Callback-реестр в `checker.py` |

### 3.4 Ограничения и рекомендации для внедрения
1. **Сессии не персистентны** — при рестарте сервера пользователи выходят из системы; для продакшена рекомендуется внешний кэш или переход на токены.
2. **SQLite выдерживает одиночный вуз** — для филиальных/облачных развёртываний перейти на PostgreSQL.
3. **200 символов минимум** в `check-text`; короткие тексты (рефераты) — отфильтровать.
4. **Ollama локальная** — GPU-сервер вуза повышает скорость AI-детекции; модель `gpt-oss:120b-cloud` уже подключена.
5. **Криптографический контур** — интеграция не должна обходить 512-bit печать: результаты проверок принимать только с валидным seal (`/verify/{seal}`).

## 4. Запуск и деплой

| Способ | Команда |
|---|---|
| Исходники | `python run_server.py` (порт по умолчанию 7932) |
| Сборка (exe) | `dist/UniPlag_Server/UniPlag_Server.exe` |
| Лаунчер | `UniPlag_Start.bat` (переменные UNIPLAG_* задаются в нём) |
| BlackBox (шифрованный контейнер) | `python run_blackbox.py` — выполнение из RAM без диска |
| Сеть | `start.bat` использует `0.0.0.0` для доступа с других машин |

## 5. Заключение

UniPlag & ICG v0.4.1 — **готов к интеграции на уровне JSON API** с LMS, порталом вуза и системами мониторинга без доработок. Для полноценной корпоративной интеграции (SSO, API-ключи, массовые очереди, Excel/CSV-выгрузки) требуется точечные доработки, перечисленные в п. 3.3. Криптографический контур (512-bit печать, манифест целостности, публичная верификация) позволяет использовать результаты проверок как юридически значимые документы.
